# stemsplits — notes for agents

- This repository owns everything stem-related: the STFT contract, the chunk
  plan, the overlap-add seam, the model weights and inference, the segment
  API, and the deployment. Wavey's app calls it; it does not duplicate it.
- **Portable Rust first.** A new op lands as clear scalar Rust with a test,
  then a SIMD kernel replaces it. Never start with the kernel.
- **No ONNX at runtime.** PyTorch and ONNX are oracles for parity tests only.
  Weights are extracted into our own bundle format, exactly as `encodec-rs`
  did. `encodec-rs` is the reference for how to do this, including
  `-ffp-contract=off` so backends agree bit for bit.
- **The seam is the contract.** The chunk plan and overlap-add here are the
  single definition for the phone, the browser and the cloud. If two sides
  can compute a different seam, that is a bug: pin the number once.
- `stemsplits-stft` is a faithful port of `StemSeparator.swift`, quirks
  included (dropped Nyquist bin, zero-frame window weights). Do not "fix"
  them; the model was trained against them. Change `StemSeparator.swift`
  first, then re-port, then regenerate the golden.
- The golden in `crates/stemsplits-stft/tests/golden/` is generated by
  `tools/oracle-stft/main.swift` on macOS. Keep the two in step.
- Model geometry, segment length and overlap are numbers, not magic: if a
  model is retrained with a different segment, add a new plan; never mutate
  the shipped one.
- Keep the deterministic-input generator in the tests identical to the one in
  the Swift oracle, so both sides see the same samples.
